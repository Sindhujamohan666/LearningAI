QABuddyAI — Backend & Architecture

Python 3.11+ LangGraph BGE-m3 Qdrant DeepSeek   Multi-Agent RAG Pipeline for QA Automation

QABuddyAI is an AI-powered Quality Assurance automation platform that ingests project documentation (PRD, SRS, meeting notes, Figma specs, JIRA tickets, Jenkins logs), extracts requirements, auto-generates test cases, executes them via Playwright/Selenium, and produces traceability reports with a Requirements Traceability Matrix (RTM).

6 specialized AI agents work in a sequential pipeline, orchestrated by a central LangGraph-based controller. The system uses BGE-m3 embeddings with FP16 acceleration and Qdrant as the vector store for Retrieval-Augmented Generation.

🔑 Key Design Decisions

  • Modular core engine — LLM client, embeddings, vector store, and document loading are decoupled for swappable implementations
  • Agent-per-concern — Each agent has a single responsibility, making the pipeline testable and extensible
  • Stateful orchestrator — LangGraph state machine tracks full pipeline state with JSON audit trail
  • Dual interface — CLI for automation/CI, Streamlit UI for interactive exploration
  • LLM abstraction — Single get_llm() factory supports Ollama, OpenAI, Anthropic, and DeepSeek via unified interface
  • FP16 acceleration — BGE-m3 embeddings use half-precision for ~2x speed without quality loss
  • Two-stage retrieval — Vector search (top-k×2) → cross-encoder re-rank (top-k) for precision

embeddings.py — BGE-m3 + Re-ranker

Wraps FlagEmbedding library for state-of-the-art dense embeddings and cross-encoder re-ranking.

def embed_documents(texts: list[str]) -> list[list[float]]:
    model = get_embedding_model()  # BGEM3FlagModel, FP16, lazy-init
    output = model.encode(texts, return_dense=True, return_sparse=False)
    return output["dense_vecs"].tolist()  # 1024-dim vectors

def rerank(query: str, documents: list[str], top_k: int = 5) -> list[dict]:
    reranker = get_reranker()  # FlagReranker, FP16, lazy-init
    pairs = [[query, doc] for doc in documents]
    scores = reranker.compute_score(pairs)
    return sorted(ranked_pairs, key=lambda x: x["score"], reverse=True)[:top_k]

Lazy initialization — models are loaded once on first call, then reused via global singleton. FP16 acceleration is controlled by the BGE_USE_FP16 env var.

orchestrator.py — LangGraph State Machine

The orchestrator chains all 6 agents into a deterministic 7-phase pipeline. It maintains a state dictionary that propagates through each phase:

class Orchestrator:
    def __init__(self, data_dir, framework, output_dir, push_jira):
        self.doc_analyzer = DocumentAnalyzerAgent()
        self.test_generator = TestGeneratorAgent()
        self.test_executor = TestExecutorAgent()
        self.cicd_agent = CICDAgent()
        self.reporter = ReporterAgent()
        self.jira_agent = JiraAgent()
        self.state = {
            "documents_ingested": 0,
            "requirements": {},
            "test_cases": [],
            "test_results": [],
            "report_path": "",
            "jira_tickets": [],
            "errors": [],
        }

Error handling: Each phase is wrapped in try/except. Failures are collected in state.errors[] and the pipeline continues to subsequent phases. The full state is saved as pipeline_state_*.json for audit.

Programmatic Usage

All components can be used directly in Python scripts:

from src.agents.orchestrator import Orchestrator

# Run full pipeline
orch = Orchestrator(
    data_dir="./data",
    framework="playwright",
    output_dir="./reports",
    push_jira=False,
)
state = orch.run()
print(f"Generated {len(state['test_cases'])} test cases")
print(f"Report: {state['report_path']}")

# Individual agents
from src.agents.document_analyzer import DocumentAnalyzerAgent
agent = DocumentAnalyzerAgent()
agent.ingest("./data")
response = agent.analyze_document("What are the edge cases for checkout?")
print(response)
